### Runtime Data Verification (performed, not assumed)

`grep`-confirmed both storage adapters resolve their target directory via `process.cwd()`, not `import.meta.url`/`__dirname` or any path relative to the adapter file's own location:
- `lib/website-builder/siteStorage.js` — `path.join(process.cwd(), "website-builder-sites")` (or `WEBSITE_BUILDER_SITES_DIR`)
- `lib/website-builder/backupStorage.js` — `path.join(process.cwd(), "website-builder-backups")` (or `WEBSITE_BUILDER_BACKUPS_DIR`)

Since `process.cwd()` is the Node process's working directory (repo root when run via `npm run <script>`), not the module file's location, moving these two files to `modules/website-builder/storage/` does not change which directory they read from or write to. This will be re-confirmed after the move by running the existing `test-website-publish-integrity-regression.mjs` and `test-website-footer-navigation-regression.mjs` scripts, which exercise this storage path indirectly, and by manually inspecting an existing project ID/slug in `website-builder-sites/` before and after the move to confirm it's still readable through the relocated adapter.
