# Inclusions Selections Domain Model

Date: 2026-07-29

## Core Entities

- `AreaGroup`: builder-defined grouping such as whole project, living areas, wet areas, external areas, or services.
- `AreaType`: reusable type such as bedroom, bathroom, kitchen, garage, or external living.
- `ProjectArea`: an explicit project room or area. Products cannot create these.
- `AreaTemplate`: a versioned set of requirement definitions for one area type.
- `ProjectRequirement`: a generated project-specific selection need.
- `InclusionTier`: named tier: Classic, Premier, Premium, or Custom.
- `TemplateStageConfiguration`: project-owned inheritance configuration for project, AreaGroup, AreaType and ProjectArea template/tier overrides.
- `SavedBuilderTemplate`: organisation-scoped reusable template assignment structure.
- `ProductReference`: a stable selection-facing reference to a catalogue product or allowance.
- `ProjectSelection`: draft/submitted/approved/locked product or allowance choice for one requirement.
- `SelectionLocation`: the physical usage location for a ProjectSelection, preserving area, requirement, quantity, pricing quantity and unit.
- `RequirementNote`: structured internal, supplier, installation, override or Not Applicable note attached to a requirement.
- `RequirementAttachmentReference`: reference to product images, specifications, samples, quotes, drawings or manual selection images.
- `SelectionReviewState`: project review metadata for selected review view, status and Ready for Approval state.
- `ReviewIssue`: derived review issue with stable ID, severity, scope, resolution action and blocking status.
- `AllowanceOverride`: review-stage record of previous and new allowance values with actor and reason.
- `ReviewAuditEvent`: compact audit record for review actions without duplicating selection data.
- `SelectionApproval`: builder/client/admin decision attached to a selection.
- `SelectionSnapshot`: immutable locked record of selection lines.
- `EstimateSelectionExport`: estimate-facing output generated from a locked snapshot.

## Identity Rules

- All project-owned entities carry `organisationId` and `projectId`.
- Repository contracts require callers to pass a scope.
- In-memory repositories reject writes outside the requested organisation scope.
- Generated IDs are stable enough for tests and deterministic previews, but database-backed IDs can replace them later.

## Area Naming

Area names are unique only among siblings. The same label can exist in different hierarchy levels or parent areas when it represents a distinct project area.

## Requirement Lifecycle

Requirements are generated from templates and can be:

- `required`: must be selected and approved before locking.
- `optional`: can be selected but does not block locking.
- `conditional`: generated for review where applicability depends on project context.
- `not_applicable`: retained as typed structure where a decision is intentionally excluded.
- `obsolete`: no longer generated by the current template.
- `blocked_obsolete`: obsolete but still important enough to require review before removal.

Protected requirements are never silently deleted when they have selections, approvals, pricing data, downstream references or manual customisation.

## Product Compatibility

Compatibility is requirement-first. A product can satisfy a requirement only when category, subtype, active state, area type, and internal/external constraints match.

## Workspace Views

Room View and Category View are presentation choices over the same ProjectRequirements. They must not create separate category-only records. Every draft choice remains attached to a ProjectRequirement and every physical usage remains traceable through SelectionLocation.

## Product Adapter Boundary

Workspace product search and lookup flow through `ProductSelectionCatalogueAdapter`. Development fixtures may live behind the adapter, but the selections module does not own Product Library or Supplier Library persistence.

## Review Projections

Stage 4 ReviewLine, room review, category review, variation summary, client projection and builder internal projection are calculated views over ProjectRequirement, ProjectSelection and SelectionLocation records. They do not replace those records.
